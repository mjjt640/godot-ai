# AGENTS.md

## Godot 插件选择规则

这个项目在 `res://addons` 下包含两个编辑器插件：

- `godot_mcp`（`Godot MCP Native`）
- `hasturoperationgd`（`HasturOperationGD`）

使用下面的规则在它们之间做选择。

### 插件职责

- `godot_mcp` 是默认集成路径。  
  用于结构化编辑器访问、项目检查、场景和脚本查询、可重复自动化，以及 agent 驱动的工作流。

- `hasturoperationgd` 是回退执行路径。  
  当 `godot_mcp` 没有提供所需能力时，用它在编辑器内执行一次性的 GDScript。

### 默认选择规则

- 优先使用 `godot_mcp`。
- 只有当 `godot_mcp` 不能直接完成任务，或者完成成本明显高于一段短小、目标明确的脚本时，才使用 `hasturoperationgd`。

### 适合使用 `godot_mcp` 的情况

- 读取项目、场景、脚本或编辑器状态
- 执行标准化、可重复的编辑器操作
- 构建需要保持可预测、可审计的 agent 工作流
- 通过稳定接口暴露 Godot 能力

### 适合使用 `hasturoperationgd` 的情况

- 快速测试一个小型编辑器侧想法
- 运行一次性的自定义 GDScript 片段
- 访问 `godot_mcp` 还没有覆盖到的编辑器 API
- 在决定是否把某个能力正式收进 MCP 之前做探查或调试

### 冲突规避

- 不要同时用两个插件修改同一个场景、节点树或脚本。
- 如果两个插件都能解决问题，选择 `godot_mcp`。
- 如果使用 `hasturoperationgd` 作为回退方案，脚本必须保持小而专一。
- 某个 `hasturoperationgd` 工作流如果被重复成功使用，后续应考虑把它提升为 MCP 能力。

### 简短判断法

- 如果任务更像一次 API 调用，就用 `godot_mcp`。
- 如果任务更像一次临时编辑器控制台命令，就用 `hasturoperationgd`。

## 文档语言规则

- 主要给用户阅读的文档默认使用简体中文。
- 这包括设计说明、实现计划、架构文档、进度文档和交接文档。
- 代码标识、API 名称、文件名和少量更清晰的技术术语可以保留英文。
- 如果某份已有英文文档是要展示给用户看的，优先翻译或改写成中文，而不是并行维护第二份版本，除非用户明确要求双语输出。

## 项目架构护栏

- 这个项目必须把玩法规则、数据配置、表现层和胶水代码分开。
- 不要引入一个包揽无关职责的 `GameManager` 或 `XXXManager`。
- 静态配置优先使用 `Resource` 数据对象；运行时状态必须保存在运行时对象中，不能写进共享静态数据。
- 模块构筑武器系统必须保持当前 build 状态和武器结算结果的单一真相来源。
- UI 不能拥有或重算玩法规则，它只负责读取状态并展示。
- 子弹对象和命中对象只执行已经结算好的行为，不负责重新组装 build 逻辑。
- 优先扩展现有系统，不要轻易新建职责重叠的平行系统。
- 使用 AI 辅助实现时，先定义清楚文件合同，不要为了未来功能提前做猜测式抽象。

## 产品实现约束

- 除非用户明确要求，不主动添加备用输入、替代操作、兜底功能、兼容分支或“顺手保留”的第二套路径。
- 用户指定一种操作或玩法方案时，只实现该方案，不额外扩展备用方案。
- 如果认为某个备用方案有必要，先说明理由并等待用户确认，不能直接写进项目。

## 项目架构要求

- 在讨论、设计或实现玩法系统时，遵循 `docs/superpowers/specs/` 下的项目架构文档。
- 这个仓库里的用户可见说明、设计笔记和架构总结默认使用中文。
- 把 `build_state` 视为当前局内 build 的唯一真相来源。
- 把 `module_applier` 视为唯一负责把 build 选择结算为武器行为的地方。
- 把 `shot_profile` 视为武器执行边界对象。
- 所有会改变流程的效果都应挂在固定战斗阶段上，不要发明新的战斗主循环。
- 静态平衡数据优先使用 `Resource`，在可行情况下保持一条记录一个文件，并确保运行时状态不进入这些资源。
- 除非用户明确要求扩展成更大的数据管线，否则不要把 JSON 或数据库作为这个项目的主平衡数据格式。
- 如果未来平衡编辑需求变大，优先采用 `CSV -> Resource` 的导入路径，而不是改成运行时直接读 CSV。
- 模块槽位的语义必须固定，尤其是 `fire_mode` 和 `payload`。
- 升级、伤害结算、武器组装和静态数据访问不要平行新建第二套系统，除非现有系统已经无法干净扩展。
- 用 AI 写代码时，任务粒度要收敛到文件级合同，并验证生成代码引用的 API、路径和数据流是否与当前项目结构一致。
